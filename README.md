1. GeneratePreset - создаёт армию для компьютера
Сначала считаю для каждого юнита отношение атаки к стоимости - это эффективность. Сортирую по эффективности - самые эффективные сначала.
Потом беру самый эффективный тип и добавляю его в армию, пока не кончатся очки или не наберу 11 штук одного типа. Координаты ставлю случайно на левой стороне (x от 0 до 2). Если клетка уже занята - пробую другую.

2. SuitableForAttackUnitsFinder - ищет кого можно бить
Смотрю все юниты противника. Юнит подходит для атаки, если он не закрыт своим же юнитом.
Если мы атакуем левую армию (компьютер), то смотрим, нет ли справа от юнита другого юнита его армии. Если нет - значит можно бить.
Если атакуем правую армию (игрока), то смотрим слева.

3. UnitTargetPathFinder - ищет путь для атаки
Поиск в ширину. Поле 27x21 клеток. Каждую клетку проверяю: если там живой чужой юнит (кроме цели) - нельзя ходить.
Можно ходить в 8 направлениях (и по диагонали тоже). Иду от атакующего к цели, запоминаю откуда пришёл. Потом восстанавливаю путь назад.

4. SimulateBattle - сам бой
Бой идёт по раундам. В каждом раунде:
Собираю всех живых юнитов и сортирую по силе атаки (сильные ходят первыми)
Каждый юнит атакует по очереди(вызывает свой program.attack())
Если юнит умирает до своего хода - раунд начинается заново и когда все походили - конец раунда. Так продолжается, пока в одной из армий не кончатся живые юниты.

GeneratePreset: Сортировка типов + добавление юнитов. Получается где-то O(N·T), где N - сколько юнитов, T - сколько типов (всего 4 типа).

SuitableForAttackUnitsFinder: Просто прохожу по всем юнитам в трёх рядах. O(U), где U - сколько юнитов.

UnitTargetPathFinder: Обхожу всё поле 27x21. Это константа - 567 клеток. O(1) по сути.

SimulateBattle: В каждом раунде сортирую юнитов - O(N log N). Раундов может быть много, но обычно не больше чем юнитов. Получается O(N²) в худшем случае.
